# Add a sponsors information page

Slug: elixir-menu-sponsors-page-20261121
Model: not applicable — the change is a static page, static discovery links and generated text; it has no meaningful state
Acceptance:
- .kogen/intents/elixir-menu-sponsors-page-20261121/acceptance.feature
- features/steps/elixir-menu-sponsors-page-20261121__site.js

Add a static `/sponsors/` business-information page to elixir.menu, rendered through the existing Information layout (`src/layouts/Information.astro`) with the existing Index visual identity, header, footer and brand assets. The page explains how a coding agent uses Elixir Menu to choose tools for a task and how a relevant, optional sponsor could fit with a clear disclosure and with the user keeping the choice. It may include one short illustrative Elixir-specific workflow, labelled as an example. It states that no sponsor is active and that the sponsor formats and the agent behavior it describes are not approved or available yet. It keeps commercial details out: it has no price, discount, traffic or campaign figure and no Plausible or Cloudflare name or dashboard link. It explains visitor protections in the section next to the offer, and gives an inquiry link (`mailto:`) to the existing verified product contact for pricing and audience numbers.

The page is linked from the shared public footer (`content/footer.html`), listed in the agent index `llms.txt` under a new "Business information" heading, and added to the built sitemap through the existing convention in `scripts/build-agent-content.py`. The page has a title, a meta description and a canonical URL through the existing layout. One route only: `dist/sponsors/index.html`.

The existing tool exports (`stack`, `app-guide`, `optional`, `runtime` in `.json`, `.md` and `.json.md` forms, and `setup.md`) stay byte-identical to the build at HEAD and mention no sponsor. Recommendations, alternatives, rankings and independent criteria are untouched. The build output is `dist/`, produced by `npm run build`; no deployment is part of this change.

Each acceptance check runs on its own in under 30 seconds after one build, reads only the built `dist/` output, runs no whole test suite and uses only tools the checkout already provides. A check that cannot start (for example no installed Chrome) exits with a code different from both its pass code and its fail code.

The agent index entry is the `/sponsors/` line under "## Business information" in `dist/llms.txt` (generated by `scripts/build-agent-content.py`; `public/llms.txt` is the authored base). The page and the entry must contain, in the page text (and, for the last two, in the entry text): a sentence about a sponsor that says it is "optional" and "disclosed"; the words "the user keeps the choice"; the page also says "no active sponsor" and "not yet available" (or "not approved"/"not live"). The page has an `h2` containing "Visitor protections" in the same section as, or directly next to, the section holding the inquiry link, and that section mentions disclosure and choice. A workflow, if present, sits under a heading containing "Example".
